# Source changes

The old global five-tick full HUD rebuild is removed. The five-tick maximum vitals/combat probe interval remains, staggered by UUID. A probe compares primitive values or cached bindings before scheduling work. A cast/progression/equipment mutation signals the affected player by UUID. No worker reads Minecraft players, worlds, registries, inventories, attribute containers or BEconomy.

The pipeline is:

```
mutation / changed probe → domain revision
→ budgeted main-thread capture → detached immutable JSON values
→ bounded shared executor: transform, Gson, compression
→ main-thread UUID / session / revision validation → packet dispatch
```

Domains: VITALS, COMBAT, CLASS, EQUIPMENT, EXTENSIONS, COMMERCE, GUI, BUNDLES. Each player/domain has at most one pending or running capture. New changes coalesce; obsolete completions are discarded and the latest revision is retained. Domain queues rotate an aging slot to avoid GUI starvation under continuous combat/catalog work. The default is two workers, 64 in-flight reservations, at most 16 captures and two GUI/catalog captures per tick, with a 2 ms soft main-thread budget. One native capture/provider call cannot be preempted; a cold item/formula call can exceed that budget.

Workers receive no live game objects. `FrozenValues` rejects non-JSON objects and non-string map keys; snapshots have structural bounds. Shared definition trees are frozen once. Each stamp contains player UUID, session generation, domain revision and sequence. Respawn/dimension changes create a new generation. Disconnect cleanup is marshalled to the server thread; native session identities detect a rapid reconnect and offline sessions are reconciled defensively. GUI close/expiry and shutdown cancel obsolete work. Capture and dispatch enforce server-thread ownership.

## Definitions and invalidation

- Combat bindings, names, icons and calculated parameters are rebuilt on class/progression/equipment/mode changes. Native skill-runtime refresh covers external skill providers. Active casts and cooldown deadlines are independent small updates. The client animates cooldowns from deadlines, including cached skill-menu rows.
- Vitals are primitive observations; unchanged observations schedule nothing. Rider state is compact. Hero HUD no longer calls the debug inspector or scans debug history.
- Shop reload invalidates commerce/catalog and any open class policy view; it does not rebuild unrelated HUD metadata.
- Class descriptions and configured skill presentation are cached by native class definition identity, bounded to 512 entries and cleared by global invalidation/stop. Player-dependent formulas remain on the server thread.
- Profile and Pokémon skill definition DTOs are cached per session until class, equipment, progression or GUI mutation invalidation. They are not final-JSON TTL caches.
- Shop definitions are validated on load/reload. Immutable row templates and item preview encodings are shared by configuration/Items registry revision. Quotes use a direct product index instead of a per-row linear search.
- Native item previews are prepared in bounded main-thread slices. A stable preview reference is sent with each offer; the native component/NBT table is sent once per session/static revision. Actual reward ItemStacks are generated by the existing authoritative grant path.
- A closed shop performs no catalog generation or balance polling. Open-shop display balances use at most two scheduled provider polls per tick, at a minimum one-second interval per player. Explicit changes invalidate the display DTO. Every purchase independently validates authoritative balances/prices on the required server thread.
- GUI patches do not contain authoritative vitals/class/stat fields. Commerce balances overlay late catalog results. GUI scope changes cancel old work before replacement capture. Client per-domain fences reject obsolete patches before application.
- Belt optional-API reflection metadata is resolved once; live equipped stacks are still queried through the installed APIs. There is no stale ItemStack TTL cache.

## Instrumentation

`/fantasyhubperf` preserves the previous counters and adds HUD capture/serialization, per-domain captures, immutable definition cache reuse, preview cache hits/misses, queue/active-worker/completion lengths, submitted/completed/coalesced/stale/error counts, serialized and encoded payload sizes, capture-to-dispatch latency and total sync tick work. Timing rings hold 2,048 samples. Mean/max cover the reset window; P95/P99 cover the bounded recent sample ring. Sorting occurs only on the operator query, not each tick. The `inFlightAtReset` gauge records work queued before a reset, so submitted/completed counts can be reconciled across the reset boundary. HUD update counts in 0.3.0 mean committed realtime packets; 0.2.9 counted attempted HUD builds, so those counters are not directly interchangeable.

SNAP, boss AI, damage, teleportation, inventory grants, currency transactions and registry access remain on their existing required threads. No related mod is disabled to obtain a better result.
